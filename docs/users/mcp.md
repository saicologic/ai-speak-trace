# MCP サーバーで会話を聞く

[使い方に戻る](usage.md)

この Mac の AI Speak Trace で文字起こしした会話について、MCP に対応したクライアント（Claude Code・Claude Desktop など）のチャットで質問できるようにする機能です。[MCP](https://modelcontextprotocol.io/)（Model Context Protocol）という仕組みで、クライアントがアプリのデータを読み取ります。

- 登録の手順は、[使い方の「MCP サーバー」](usage.md#11-mcp-サーバーclaude-desktopclaude-code-から会話を読む) を確認してください
- 設計の理由は、[MCP サーバーの設計](../developers/mcp-server.md) を確認してください
- データの扱いは、[PRIVACY.md の「MCP サーバー」](../../PRIVACY.md#mcp-サーバー) を確認してください

## できること

- 文字起こしした会話の一覧を見る
- 会話の内容を、最初から順に読んでもらう
- 話題や言葉で、発言を探してもらう
- 見つかった発言の前後を読んで、話の流れを説明してもらう
- 会話でよく出てきた言葉を教えてもらう

対象は、この Mac にあるアプリのデータ（文字起こしした会話）だけです。ほかのサービスのデータや、チャットの履歴は読みません。アプリを開いていなくても使えます。会話を書き換える機能はありません。

## 利点

- **アプリを開かずに聞ける**: MCP に対応したクライアントのチャットから、そのまま質問できます。アプリの名前を言わなくても、「文字起こしした会話」と言えば使われます
- **根拠付きで答える**: 返す発言には、話者と時刻（例: `Aさん 17:27`）が付きます。答えの根拠になった発言を、アプリで聞き直して確かめられます
- **個人情報を伏せて渡す**: 個人情報チェックを済ませた会話だけを、伏せ字にして Claude に渡します。名前は `[氏名]`、電話番号は `[電話番号]` のように置き換わります
- **必要なところだけ読む**: 会話を丸ごと渡すのではなく、検索や前後の読み取りで、必要な発言だけを渡します。長い会話でも、聞きたいところだけを答えてもらえます
- **記録が残る**: いつ、どの機能で、どの会話を読んだかを記録します。発言の本文は記録に残しません

## 機能ごとの説明

### 会話の一覧（`list_transcriptions`）

文字起こしした会話を、新しい順に返します。

- 返すもの: 会話の id（`t_` で始まる文字列）・作成日時・話者名・発言の数・読めるかどうか（`privacy`）
- 読めない会話には、読めない理由とアプリでの対処を付けます（下の「[読めない会話](#読めない会話)」）
- 音声ファイル名は返しません。会話の id は音声ファイル名を含まない値で、MCP サーバーを起動するたびに変わります

### 発言を順に読む（`get_utterances`）

1つの会話の発言を、指定した番号から順に返します。

- 1回に返す発言は、既定で50件、多くて100件です。続きがあるときは、続きを読むための番号（`nextFrom`）を返します
- 返す発言には、話者名・開始と終了の時刻・引用の表記（`cite`、例: `Aさん 4:22`）を付けます
- 2,000文字を超える長い発言は、途中で切って `truncated: true` を付けます

### 発言の検索（`search_utterances`）

言葉で発言を探し、見つかった発言を返します。

- 空白で区切ると、すべての言葉を含む発言だけを返します。全角と半角、大文字と小文字は区別しません
- 話者名で絞り込めます（例: `Aさん`）
- 1回に返す発言は、既定で20件、多くて50件です
- 伏せ字にした後の本文で探すため、伏せた名前などでは見つかりません

### 発言の前後を読む（`get_context`）

1つの発言と、その前後の発言を返します。

- 前後に返す発言は、既定でそれぞれ3件、多くて10件です
- 中心の発言には `center: true` を付けます
- 検索で見つけた発言が、どういう流れで出てきたのかを確かめるときに使います

### 会話のキーワード（`get_keywords`）

アプリの GiNZA のキーワード抽出（ベータ機能）で抽出したキーワードを、出てきた回数の多い順に返します。

- 多くて100件を返します。話者で絞り込めます
- アプリでキーワード抽出をしていない会話では、`status: "not_extracted"` を返し、キーワードは空です。抽出の後に文字起こしが変わった場合は `status: "stale"` を返します。どちらも、アプリで GiNZA のキーワード抽出をすると返るようになります
- 伏せた文字列や連絡先を含むキーワードは返しません

## 質問の例と、使われる機能

ふだんの言葉で質問すると、クライアントが必要な機能を選んで使います。質問には「文字起こしした会話」と入れて、対象をはっきりさせてください。次の表は、テストに使った Claude Desktop で試したときに使われた機能です。

| 質問の例 | 使われる機能 | 答え方 |
|---|---|---|
| 最近文字起こしした会話には、どんなものがある？ | 会話の一覧 | 読める会話と、読めない会話の理由を答える |
| いちばん最近文字起こしした会話では、どんな話をしていたか教えて | 発言を順に読む | 会話の流れを要約する |
| いちばん最近文字起こしした会話で、次にやることを決めていたのはどのあたり？ | 発言の検索（見つけた場所の前後を、発言を順に読むで読むこともある） | 話者と時刻を付けて、その話の場所を答える |
| そこは、どういう流れでその話になったの？ | 発言の前後を読む（発言を順に読むが使われることもある） | 前後の発言から、話の流れを説明する |
| いちばん最近文字起こしした会話で、よく出てきた言葉は？ | 会話の一覧、会話のキーワード | アプリで GiNZA のキーワード抽出をした会話なら、キーワードを出てきた回数と一緒に答え、どんな話だったかもまとめる。抽出していなければ、アプリで抽出するよう案内する（目立つ言葉で発言を検索して、出てくる数を数えて答えることもある） |
| ゲストの人の名前は何て言ってた？ | 発言の前後を読む（すでに読んだ発言から答えることもある） | 名前は `[氏名]` と伏せてあるため、分からないと答える |
| （一覧を聞いた後に）もう1つの会話も、どんな話だったか教えて（読めない会話のとき） | 会話の一覧 | 読めない理由と、アプリでの対処を案内する |

**使われる機能が変わる場合**

- 同じ質問でも、使われる機能が変わることがあります。たとえば前後の流れを聞くと、「発言の前後を読む」の代わりに「発言を順に読む」でその範囲を読むことがあります
- 同じチャットで会話を読んだ後は、機能を使わずに、すでに読んだ内容から答えることがあります。検索や前後の読み取りを使ってほしいときは、新しいチャットで質問してください
- 「昨日の会話」のように、文字起こしした会話だと分からない言い方では、この機能が使われないことがあります
- 「昨日文字起こしした会話」のように日付で聞くと、その日に文字起こしした会話がないときは、いちばん新しい会話で答えることがあります。日付にかかわらず確かめるときは「いちばん最近文字起こしした会話」と聞いてください

## 読めない会話

個人情報チェックを済ませていない会話は、Claude に渡しません。会話の一覧には出ますが、中身は読めず、次の理由を返します。

| 状態（`privacy`） | 理由 | アプリでの対処 |
|---|---|---|
| `unchecked` | 個人情報チェックをしていない | ディープサーチで会話を選び、個人情報チェックをする |
| `needs_review` | 個人情報チェックに「要確認」が残っている | ディープサーチの「個人情報チェック」で、伏せるかどうかを選ぶ |
| `stale` | 個人情報チェックの後に、文字起こしが変わった | ディープサーチの「個人情報チェック」で、もう一度確認する |
| `error` | 文字起こしやチェックの結果を読めなかった（保存中など） | しばらくしてから、もう一度試す |

読める会話は `checked` です。読めない会話の中身を読もうとすると、Claude は上の理由を伝えます。

## 動作確認する場所

テストには Claude Desktop を使います。

- テスト用のプロジェクト（例: 「AI Speak Trace MCP テスト」）を作り、その中の新しいチャットで試してください。ふだんのチャットと分けると、ほかの話題が答えに混ざりにくくなり、テストのチャットも見返しやすくなります。プロジェクトの「指示」と「コンテキスト」は空のままにしてください。指示を書くと、ふだんの言い方で機能が使われるかを確かめられません
- 新しいチャットを始めるたびに、入力欄の「＋」で「メモリ」をオフにしてください。新しいチャットでは、オンに戻っています。オンのままだと、Claude とのチャットの履歴が答えに混ざります
- 機能を使うたびに許可を求められるので、「1回だけ許可」を選んでください
- 検索や前後の読み取りを確かめるときは、新しいチャットで、要約を頼む前に聞いてください。同じチャットで会話を要約させると、会話を全部読み込むため、その後の質問では機能が使われずに、読み込んだ内容から答えます

| 確かめること | 場所 | 見るところ |
|---|---|---|
| つながっているか | Claude Desktop の「設定」→「開発者」 | `ai-speak-trace` が running になっている |
| 使えるようになっているか | チャットの入力欄の「＋」→「コネクタ」 | `ai-speak-trace` がオンになっている |
| どの機能が使われたか | チャットの答えの上の「ai-speak-trace: …」 | 機能の名前（例: `Search utterances`）が出る |
| 返ってきた内容 | 「ai-speak-trace: …」を開いたときの「レスポンス」 | 会話の id が `t_` で始まる。音声ファイル名が出ない。名前などが `[氏名]` のように伏せてある |
| 呼び出しの記録 | データの保存先の `mcp-audit-logs/`（月ごとのファイル） | 呼び出しごとに1行増える。発言の本文は入っていない |
| つながらないときの原因 | `~/Library/Logs/Claude/mcp-server-ai-speak-trace.log` | 起動のエラーが出る |
| 架空の会話で試す | `cd backend && npm run mcp:inspect`（MCP Inspector がブラウザで開く） | 5つの機能を画面から呼んで、結果を確かめられる。手元の会話は読まない |

データの保存先は `~/Library/Application Support/io.github.saicologic.ai-speak-trace/data/` です。

## 気をつけること

- **会話の内容は Anthropic に送られます**: 返した発言は、登録した Claude Desktop・Claude Code を通じて Anthropic に送られます。送られるのは、伏せ字にした後の発言です
- **伏せられないものがあります**: 伏せるのは、個人情報チェックで「伏せる」にした文字列と、電話番号・メールアドレスなど形の決まった連絡先です。チェックで見つからなかった個人情報（形の決まっていない ID など）は、伏せずに返ることがあります。残したくない文字列は、個人情報チェックで「伏せる」にしてください
- **アプリでの設定とは別に動きます**: 設定の「AI 分析を使う」とは連動しません。アプリを起動していなくても使えます
- **プロンプト攻撃の確認はしません**: アプリから Claude に送るときとは違い、Amazon Bedrock Guardrails での確認は通しません
- **Claude Code では、データのフォルダを直接読ませない設定をしてください**: 設定しないと、MCP サーバーを通さずに、伏せ字にしていない会話が読まれることがあります。設定の例は [使い方の「MCP サーバー」](usage.md#11-mcp-サーバーclaude-desktopclaude-code-から会話を読む) にあります
