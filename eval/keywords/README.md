# キーワード抽出の比較（実験用）

今のアプリのキーワード抽出（`frontend/src/utils/keywords.ts` の `extractKeywords`、正規表現だけ）と、
形態素解析・固有表現抽出を使う手法を、人がつけた正解で比べる実験用のプロジェクト。
効いた手法だけを後で TypeScript に移す。**ここではアプリは変えない。**

- uv で、`eval/keywords/` だけの独立したプロジェクトにしている（Python 3.12）
- 有料の API は使わない
- 実データ（`.data/`）と実行結果（`results/`）はコミットしない（`eval/keywords/.gitignore`）

## 準備

```sh
cd eval/keywords
uv sync          # SudachiPy・GiNZA・wordfreq・pytest を入れる（辞書・モデルで約 400MB）
uv run pytest    # 指標・C-value・各手法の小さなテスト
```

今の手法は Node（22.18 以上、型の除去が標準で有効な版）で `keywords.ts` を直接読み込んで実行する。

## 1. データをコピーする

使う実データは **B5AAEA5F（前編）と 9F5F9DEC（後編）の2件だけ**。

```sh
uv run python scripts/copy_data.py
```

`~/Library/Application Support/io.github.saicologic.ai-speak-trace/data/transcriptions/<ID>/transcription.json`
を `.data/transcriptions/<ID先頭8文字>/` にコピーする。アプリのデータには書き込まない。

## 2. 正解を作る

1. 候補の一覧を作る

   ```sh
   uv run python scripts/make_candidates.py
   ```

   全手法の結果を合わせ、表記をそろえて重ねたものを `.data/gold_candidates.tsv` に書き出す
   （語・見た目の種類・見つけた手法・会話ごとの出現回数）。`.data/gold.tsv` があれば判定を引き継ぐ。

2. 文字起こしを通して読み、どの手法も拾えなかった専門用語・固有名詞も足す

3. `.data/gold.tsv` を作る（タブ区切り）

   | 列 | 中身 |
   |----|------|
   | `term` | 語 |
   | `label` | `1` = 正解、`0` = 正解ではない |
   | `type` | `漢字` / `カタカナ` / `英字` / `複合` / `固有名`（`label` が 1 のとき） |
   | `aliases` | 同じものとして数える別の書き方（`\|` 区切り）。音声認識の誤りや表記ゆれ |
   | `note` | メモ（「境界」は判断が分かれそうな語） |

   - 候補にある語はすべて 0 か 1 をつける。正解ファイルにない語を手法が出すと「未判定」として誤りに数え、件数を表に出す
   - 正解の語がどちらの会話に出てくるかは、本文を検索して決める（`type` と `aliases` を見る）

4. 正解を確かめて確定する。確定するまで、最終の数字は出さない

### 正解の基準

- 正解にする：AI・ソフトウェア開発の専門用語、人名・組織名・製品名・サービス名・イベント名・記事名
- 正解にしない：日常でも同じ意味で使う一般語（評価・学習・開発・モデル・プロダクト・ループ など）、
  地名、敬称つきの語（`Chip Huyenさん`）、固有名の一部だけ（`Code`・`Judge`・`Reilly`）、
  音声認識の誤りで別の語になったもの（`吉田` ←「よしなに」）
- 同じものの別の書き方は1つの語にまとめ、`aliases` に入れる（例：`加賀谷` に `Kagaya`・`カガイ`・`金井` など、
  `RAG` に `ラグ`、`Claude Code` に `クラウドコード`）

## 3. 実行する

```sh
uv run python scripts/run_eval.py
```

`results/<日時>/` に次を保存する。

- `methods/<手法>.json`：会話ごとの抽出結果（語・点数・出現回数）と処理時間
- `metrics.json`：手法ごとの指標
- `report.md`：比べた表

## 比べる手法

| 名前 | 中身 |
|------|------|
| `regex` | 1. 今の手法（基準）。`baseline/extract_regex.mjs` で `extractKeywords` をそのまま実行する |
| `sudachi` | 2. SudachiPy（分割単位 C、SudachiDict core）で名詞の連続を取り出し、C-value で並べる |
| `ginza` | 3. GiNZA（`ja_ginza`）の固有表現（数・日時などを除く）と、名詞句の主要部を含む名詞の連続 |
| `combined` | 4. 2 の C-value を 0〜1 にそろえ、3 の固有表現なら 1 点足す |
| `*+freq<Z>` | 5. wordfreq の日本語の頻度表で、Zipf 値が Z 以上の語を除く。固有名詞は除かない |

- どの手法にも、ディープサーチと同じく発話を改行でつないだテキストを渡す。
  Python の手法は発話ごとに解析し、`[笑い]` のような音のタグを除く
- C-value は 1語の候補も点数がつくよう、長さの重みを `log2(語数 + 1)` にしている（`kweval/cvalue.py`）
- 頻度表のしきい値は 4.0 / 4.5 / 5.0 を「頻度表のしきい値を変えたとき」の表で比べる

## 比べ方

- 適合率・再現率・F1：会話ごとに数え、2件を合計して計算する。同じ正解に当たる別の書き方はまとめて1件にする
- 種類ごと：正解の語は正解ファイルの種類、正解でない語は見た目で分ける。`固有名` は再現率だけを見る
- P@30：点数の高い順に上位 30 件の適合率（ディープサーチに渡すのが上位 30 件のため）
- 処理時間：辞書・モデルの読み込みと、1件あたりの抽出を分けて測る。今の正規表現は Node の起動時間を除く
- 今の正規表現より増えた正解・新しく出た誤り・なくなった正解の例と、どの手法も拾えなかった正解を並べる

正解は候補一覧から作るので、手法の中身を変えて新しい語が出たら、`make_candidates.py` で候補を作り直し、
未判定の語に判定をつけてから比べる。
